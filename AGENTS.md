## App rules
- Dealer risk is owner-only, requested explicitly, persisted with its input facts, and generated by server-only AI Gateway Responses helpers; never let AI mutate blocking state.
- Dealer blocking uses an owner-confirmed database RPC and a sales insert trigger; retain payment collection and serialize blocks against sales using retailer-row locks.
- Only retailer-linked returns may influence dealer risk; flag unassigned return history as missing rather than attributing salesman returns to dealers.
- Stock, sale and return changes go only through the database functions (issue_stock, record_sale, return_stock, check_imei); never write imei_units/stock_movements directly from the client — they enforce IMEI status validation.
- Salesman balances are derived from stock_movements, sales, retailer_payments and deposits (see src/lib/me.ts); do not store running totals.
- UI strings live in src/lib/i18n.tsx (Bengali + English pairs).
- Leaf page metadata uses the shared pageHead helper to keep company identity consistent with distinct page titles.
- Dashboard and stock counts use security-invoker reporting RPCs so totals aggregate in PostgreSQL without bypassing caller RLS.
- Shared queries reuse data briefly and mutations invalidate it; do not cache security decisions in browser storage.
- Blank letterhead settings fall back to the company defaults; explicit saved business settings remain editable.
- Dashboard insights use a security-invoker RPC; stock-house alerts are owner-only and retailer financial insights retain caller RLS.
- Age unallocated retailer payments against initial invoice balances oldest-first, ordered by sale timestamp and ID, without storing running balances.
- Daily and monthly reporting boundaries use the Asia/Dhaka timezone; per-product stock thresholds default to disabled until configured.
